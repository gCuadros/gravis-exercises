# Foundation preview 0.1.0 → 0.2.0

This is an unreleased development transition. No npm release or public deployment is implied.

## Breaking contract change

Exercise `schemaVersion` changes from **1 to 2**. Equipment, primary/secondary muscles and family now accept only the keys embedded in the record schema. Discipline and metric enums use the same vocabulary source. A muscle cannot appear in both primary and secondary roles. TypeScript equipment filters are now a closed union plus `all`, rather than arbitrary strings.

The generated catalogue envelopes carry `schemaVersion: 2` to identify their record contract. The standalone envelope schema was added subsequently in 0.2.1; see the [catalogue contract](../catalogue-contract.md). The distribution version becomes `0.2.0` according to the pre-1.0 incompatible-change policy.

## Migrating data and consumers

1. Keep a copy of any version 1 data. Compare its keys against the taxonomy shipped in the new archive and validate every proposed version 2 record.
2. Map unknown terms explicitly, or propose missing terms through the vocabulary workflow. Search aliases are not accepted as stored keys. Do not drop unknown fields, replace muscles or infer movement equivalence automatically.
3. Resolve any exact primary/secondary muscle overlap through editorial review, then set the record's `schemaVersion` to 2 and run validation.
4. Update consumers to the new schema and generated declarations. Validate equipment filters from user input before using them as typed keys. JavaScript search with an unknown filter still returns no results.
5. Pair exercise data, taxonomy and schemas from one package version. Rebuild the website so its client assets and embedded data agree.

All eight repository pilot records already use recognized keys with disjoint muscle roles. Their only content-file change in this migration is `schemaVersion: 2`; IDs, slugs, names, instructions and review states are unchanged. They remain drafts with no demonstrations.

## Additive exports and display behavior

The new `/taxonomy`, `/taxonomy/data` and `/taxonomy/schema` exports provide the vocabulary to other projects. Taxonomy JSON uses its own shape version 1. Public lookups take an explicit group, preventing collisions such as equipment `band` versus metric `band`, and return `undefined` for unknown terms. The internal website label helper now fails on unknown terms instead of inventing display text from a raw key. Metric assistance has an explicit ES/EN label. Search also finds vocabulary aliases and movement families.
