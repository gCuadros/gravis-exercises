# 0.3.0 — Foundation batch A and vocabulary expansion

This is a development distribution version, not a registry release. The catalogue grows from eight to 16 drafts; published exports remain empty because no technical or demonstration approval exists.

## Compatibility decision

The record and catalogue envelope retain `schemaVersion: 2`; taxonomy retains shape `schemaVersion: 1`. No fields, old keys, IDs or slugs were renamed or removed. All eight pilot JSON files are unchanged.

A pre-1.0 **minor** increment flags the addition of closed enum cases. Older exhaustive TypeScript maps/switches and a validator pinned to the older vocabulary cannot necessarily handle the new data. This matters even though the JSON shape is unchanged.

| Group     | Added keys                              |
| --------- | --------------------------------------- |
| Equipment | `dumbbell`, `squat-rack`                |
| Muscles   | `spinal-erectors`                       |
| Families  | `squat`, `deadlift`, `push_up`, `plank` |

## Consumer actions

1. Update exercise data, exercise/catalogue schemas and vocabulary from the **same** archive. Do not validate new records with an older closed-enum schema.
2. Rebuild consumers against the generated types. Extend exhaustive maps/switches and custom equipment menus for the new keys, or derive labels and choices from the exported taxonomy.
3. Keep exercise identity as the history key. A shared family or a search alias does not merge strict/assisted pull-ups, barbell/dumbbell presses, or plank/planche.
4. Honor each record's tracking notes. The new dumbbell press uses the **combined mass of both bells**; do not import a per-bell value as total load. Timed holds remain durations, not repetition estimates.
5. Select preview data explicitly for these drafts. Default imports do not expose unapproved entries. Search results may grow, so select a deliberate identity rather than assuming one match.

The [B001 record map](../batches/001-foundations.md#group-a-delivery-and-review-handoff) lists all eight new stable IDs. There are no identity migrations or redirects in this version.
